# 对话式博客 · MVP 技术要求 v0.1

> 交付物：一个**单页网站**。打开是某个人（以下简称"作者"）的一段自我介绍，下面一个对话框。访客可以点推荐问题，也可以自己提问；回答以作者第一人称给出，并附真实出处。
>
> 本文件是给 AI 编程助手（VS Code + DeepSeek）的实施规格。**先读完全文再动手**，严格按里程碑 M0→M3 推进。

---

## 0. 这份文档怎么用

## 1. 产品定义

一句话：**一个用对话来访问的博客。** 传统博客是"点开页面读文章"，这个产品是"直接问作者本人"。

三条不可违背的原则：

1. **它是博客，不是客服。** 页面读起来像一篇文章，不像微信聊天窗口。
2. **回答必须带出处。** 说到的每件事都要能指回一篇真实文章/作品。没有就说不记得。
3. **先有人，后有 AI。** 开场是作者自述，不是"您好，我是 AI 助手"。

---

## 2. 范围内 / 范围外

**范围内（v1 只做这些）**

- 单页、单人、公开访问，无需登录
- 一个对话框 + 3 条推荐问题 + 一段开场自述
- 基于本地内容库的检索增强回答（RAG）
- 回答中带出处卡片、回答后带 2 条追问建议
- 移动端可用
- 问题可通过 URL 分享（`/?q=问题文本`）

**范围外（v1 明确不做）**

- 用户注册、多租户、后台管理界面
- 语音输入输出、音频播放器（音乐只以"作品条目 + 外链"形式出现）
- 微调模型、训练
- 数据库（除可选的对话日志）
- 多语言、深色模式、主题切换
- 任何"一键生成"功能

## 5. 内容与数据模型

### 5.1 内容文件格式

文章 `content/articles/*.md`：

```markdown
---
title: 为什么我不做 X
date: 2024-03-12
tags: [产品, 判断]
summary: 一句话说明这篇在讲什么
---

正文……
```

音乐 `content/music/*.md`：

```markdown
---
title: 夜航
date: 2023-08-01
type: music
audio_url: https://...
lyrics_note: 写这首歌时在做什么
---
（可选）创作说明
```

短内容 `content/notes/*.md`：只需要 `title`（可为空）和 `date`。

**硬性要求**：每个文件必须有 `date`。出处卡片靠它排序。

### 5.2 分块与索引

`scripts/ingest.ts` 执行流程：

1. 读 `content/articles|music|notes/**/*.md`，解析 frontmatter
2. 按 **400–600 汉字**切块，块间重叠 80 字，不跨文章
3. 每块生成：

```ts
type Chunk = {
  id: string;          // "c1", "c2"… 全局自增，稳定不重排
  sourceType: 'article' | 'music' | 'note';
  sourceId: string;    // 文件名（不含扩展名）
  title: string;
  date: string;        // YYYY-MM-DD
  url: string;         // "/writing/{sourceId}"，v1 可以先留空字符串
  text: string;
  embedding?: number[];
}
```

4. 若设置了 `EMBEDDING_BASE_URL`，为每块算 embedding；否则不写 `embedding` 字段
5. 写入 `data/chunks.json`

`id` 必须在多次 ingest 之间**尽量稳定**（按文件路径 + 块序号生成，如 `a-2024-03-12-x-2`），否则已分享的对话会指错出处。

### 5.3 人设卡字段

`content/profile/persona.md` 用固定小标题，解析时按标题取段落：

```markdown
## 身份
一句话：我是谁、在做什么

## 称呼与关系
我怎么称呼访客；我们是什么关系（陌生人/读者/朋友）

## 说话方式
- 句子长度：
- 常用词（5 个）：
- 标点习惯：
- 表情符号：
- 绝不会说的词：

## 情绪表达
- 关心时：
- 不满时：
- 开玩笑时：

## 知识边界
- 懂的：
- 不懂的：
- 会被敷衍的话题：

## 口头禅
1. 「……」—— 使用频率：高/中/低
2. 「……」—— 使用频率：中
```

## 6. 运行时：一次问答的完整链路

```
用户提交问题
  → POST /api/chat  { messages: [{role, content}...] }
  → 取最后一条 user 消息作为检索 query
  → retrieve(query, k=6) 返回 Chunk[]
  → 拼系统提示（persona + 检索块，编号 c1..c6）
  → 调用模型，流式返回
  → 服务端按 ⟦META⟧ 切分：前面是正文（流式转发），后面是 JSON（解析后最后发）
  → 前端逐字渲染正文 → 收到 meta → 渲染出处卡片 + 2 条追问
```

检索规则：

- 只检索 `chunks.json`，不检索 `persona.md`（人设已在系统提示里）
- 没有相关块（最高相似度 < 0.25）时，`context` 传空，并在提示中标注"没有找到相关内容"
- top-k 固定 6，不做 rerank

## 7. 系统提示词（完整模板）

`lib/prompt.ts` 导出函数，变量用 `{{}}` 占位：

```
你是{{name}}，{{identity}}。这是你自己的网站，你正在和一位访客说话。

【你怎么说话】
{{persona_card}}

【你能说什么】
下面是从你写过、做过的东西里检索到的片段。你只能基于这些内容讲事实。

{{context_blocks}}

规则：
1. 只用上面出现过的信息。没出现过的，直接说"这个我没写过"或"不记得了"。
2. 不要用常识补全你的经历，不要推测。
3. 只沾边的内容要说"大概沾点边，但我不确定"。
4. 引用时在句末标出来源编号，格式 [[c3]]。

【回答的形状】
- 第一句就给答案或态度，不要铺垫、不要"这是个好问题"。
- 然后 1–3 句理由或细节。
- 总共不超过 150 字。对方说"展开讲讲"才写长。
- 结尾不要总结，不要反问"还有什么想了解的"。
- 第一人称。不要提 AI、模型、助手、分身，除非对方直接问。

【边界】
{{boundaries}}

【输出格式】
先写回答正文。
然后换行，输出一行：
⟦META⟧{"citations":["c3"],"followups":["...","..."]}

followups 是 2 个访客接着可能会问的问题，要具体，像博客的"相关阅读"，不要写"你还想了解什么"。
citations 只填你真正用到的编号，没有就填空数组。
```

模型参数：`temperature: 0.8`，`max_tokens: 800`。

## 8. 输出协议

模型原始输出示例：

```
我 2019 年停更，是因为那套方法我自己不信了。[[c2]]

⟦META⟧{"citations":["c2"],"followups":["那你后来信什么？","停更那半年在干嘛？"]}
```

服务端处理：

1. 用 `⟦META⟧` 切分，正文部分逐块转发
2. 若 300ms 内没等到 `⟦META⟧` 且流已结束，视为无 meta（不报错，卡片区留空）
3. JSON 解析失败时降级：`{citations: [], followups: []}`
4. 正文里的 `[[cN]]` 标记：前端渲染成上标序号，点击滚动到对应卡片；**不要显示原始标记**

## 9. API 契约

`POST /api/chat`

请求：

```json
{ "messages": [{ "role": "user", "content": "你那篇《为什么我不做 X》里说的…" }] }
```

响应：`text/event-stream`

```
data: {"type":"delta","text":"我"}
data: {"type":"delta","text":" 2019 年"}
data: {"type":"meta","citations":[{"id":"c2","title":"…","date":"2024-03-12","excerpt":"…","url":""}],"followups":["…","…"]}
data: {"type":"done"}
```

错误：`{"type":"error","message":"…"}`，HTTP 仍为 200（流已开）。

限制：

- 单条消息 ≤ 1000 字，超出截断
- 只取最近 10 轮作为上下文
- 同一 IP 每分钟 10 次，超出返回 429

## 10. 前端规格

### 10.1 布局（从上到下，单列，最大宽度 680px，居中）

1. **页头**：作者名（衬线体，24px）+ 一行灰字"最近在写《…》"（读 `chunks.json` 里最新文章标题）
2. **开场自述**：`intro.md` 全文，正文样式，不是气泡
3. **推荐问题**：3 个横排卡片（移动端竖排），点击即发送
4. **对话区**：消息流
5. **输入框**：固定在底部，随页面滚动
6. **页脚**：一行小字"这是 {name} 的 AI 对话主页 · 由本人授权生成"

### 10.2 关键视觉决策（必须遵守）

- **不要用聊天气泡。** 助手消息按正文排版：14–16px、行高 1.8、段间距 16px，左侧一个 2px 竖线作为"引文区"标记即可。
- **用户消息**用 13px 灰色、右对齐或缩进，写成 `你：…` 的形式，视觉权重远低于回答。
- 整体读起来像一篇**有对话节奏的文章**，不是微信窗口。

### 10.3 组件行为

| 组件 | 要求 |
|---|---|
| `Intro` | 静态渲染，不做打字机动画 |
| `Suggestions` | 点击后立即禁用全部，防止连点；发送后整组淡出 |
| `Message` | 流式期间显示光标块；完成后渲染引用区 + 追问 chips |
| `CitationCard` | 显示标题、日期、80 字摘录；点击展开全文摘录；无 `url` 时不显示"阅读原文" |
| `Composer` | placeholder 必须是**示范句**，例如"问我为什么在 2019 年停更"；回车发送，Shift+回车换行 |
| 追问 chips | 点击后作为新问题发送 |

### 10.4 状态

- **加载中**：输入框禁用，显示"正在想…"（灰字，不用转圈）
- **错误**：回答区显示"没接上，再说一次？"+ 重试按钮
- **空检索**：正常回答，不显示引用区

### 10.5 URL 分享

- 页面加载时若 `?q=` 有值，自动作为第一个问题发送
- 每条回答旁有"分享这条"按钮，复制 `/?q={encodeURIComponent(问题)}`

### 10.6 响应式

- 断点 768px；移动端：全宽、边距 20px、推荐问题竖排、页头缩小
- 输入框在移动端考虑 `env(safe-area-inset-bottom)`

## 13. 验收标准

按顺序全部通过才算完成：

1. `pnpm dev` 启动后，首屏 2 秒内出现自述和 3 个推荐问题
2. 点击任一推荐问题，1.5 秒内出现第一个字
3. 回答下方出现至少 1 张出处卡片，标题和日期与 `content/` 里的文件一致
4. 回答下方出现 2 条追问，点击可继续对话
5. 问一个内容库里完全没有的事（如"你昨天吃了什么"），回答必须明确表示不知道，**不得编造**
6. 刷新带 `?q=…` 的链接，能自动复现该问题
7. 375px 宽度下无横向滚动，输入框可用
8. 逐字输出过程中页面不跳动（高度平滑增长）
9. `data/chunks.json` 里每块的 `id` 重新 ingest 后保持不变
10. 控制台无报错、无 hydration 警告

## 15. 实施顺序

- **M0 静态页面**：目录结构 + 页面骨架 + 人设卡读取 + 3 条推荐问题 + 假回答。目标是"看起来像个正经博客"。
- **M1 检索与回答**：`ingest.ts` + `retrieve.ts` + `/api/chat` 流式输出。先不做引用和追问。
- **M2 结构输出**：`⟦META⟧` 协议、出处卡片、追问 chips、`[[cN]]` 上标。
- **M3 打磨**：URL 分享、限流、错误态、移动端、性能。

每个里程碑结束**停下来**，输出：改了什么、怎么验证、有什么已知问题。

## 附录 A：`suggestions.json`

```json
[
  { "text": "你 2019 年为什么停更？", "hint": "关于那段空白期" },
  { "text": "《为什么我不做 X》里，你说后来不信了，那现在信什么？", "hint": "观点变化" },
  { "text": "你写东西的时候，第一段通常怎么起？", "hint": "创作方法" }
]
```

三条问题必须分别对应**三个不同内容领域**，且每条都能在 `chunks.json` 里找到支撑。发布前逐条测一遍，答不上来就换题。
